# سجل القرارات الهندسية (Architecture & Technical Decisions)

## 1. نموذج هجين للعرض والتشغيل السريع (Hybrid Execution Model)
- **في بيئة المعاينة التفاعلية الفورية**: تم تشغيل واجهة React + TypeScript على خادم Vite مع حالة محلية غنية ومصادر بيانات بصرية حقيقية لتمكين لجان التحكيم والمستخدمين من اختبار كافة السيناريوهات فوراً عبر المتصفح.
- **في بيئة التطوير والإنتاج الكاملة**: تم توفير معمارية الحاويات الكاملة `docker-compose.yml` مع واجهة Python FastAPI، قاعدة بيانات PostgreSQL العلائقية، وPydantic للتحقق الصارم.

## 2. النطاق الميداني الأول ومؤسسات التحقق
- التركيز على قطبين جامعيين رئيسيين للتحقق الدقيق:
  - **جامعة محمد الخامس بالرباط (UM5)** مع مؤسستها الهندسية المرموقة **ENSIAS** في مدينة العرفان.
  - **جامعة القاضي عياض بمراكش (UCA)** مع **كلية العلوم والتقنيات جليز**.
- تضمين عينات واضحة بعلامات `needs_review` و`demo` لشرح كيفية التوسع المستقبلي دون ادعاء الشمولية الزائفة.

## 3. القرار بشأن اللغات وRTL
- استخدام خط `Tajawal` العربي المعتمد والواضح جداً للقراءة الرقمية في اتجاه اليمين لليسار (`dir="rtl"`).
- زر تبديل سلس مع الفرنسية (`dir="ltr"`) مع خط `Plus Jakarta Sans`.

## 4. قرار: الأرشيف هو المنتج، والبريد مجرد جرس
- **السياق**: كان المشروع يبني بنية إرسال ممتازة (Tira) دون أن ينتج المعلومة التي تُرسل. الـpoller (كاشف التغيّر) كان مؤجَّلًا، وهو جوهر الوعد.
- **القرار**: إضافة `sources` + `fact_history` + poller + صفحة `/n/{id}` + ربط الاعتماد بالإشعار، قبل أي ميزة جديدة.
- **لماذا**:
  - `source_url` + `verified_at` + `snapshot_hash` دليل قابل للتحقق بلا حساب، ولا يُنسخ بالزمن.
  - التسليم مشكلة محلولة؛ الاكتشاف والتحقق هما الخندق.
  - صفحة `/n/{id}` هي «اللحظة» التي يرى فيها الطالب بعينه أن المعلومة تغيّرت.
- **القيود المقصودة**:
  - **إنسان في الحلقة**: الواقعة `pending` لا تُنشر ولا تُرسل قبل اعتماد. لا ندّعي أتمتة كاملة.
  - **لا إنذار كاذب في اليوم الأول**: أول قراءة خط أساس.
  - **فصل الضمانتين**: `source_url/verified_at` ليسا DKIM/SPF/DMARC، ولا يُوصفان كتوقيع من الوزارة.
  - **نطاق ضيّق**: مصدر رسمي واحد يعمل من طرف إلى طرف، لا عشرة مصادر نصف عاملة.
- **الأثر**: 21 اختبارًا جديدًا (المجموع 78) تغطي: خط الأساس، التغيّر الحقيقي، عدم التغيّر، `robots.txt`، `304`، الصفحة الفارغة، خطأ النقل، الاعتماد مرة واحدة، الرفض، صفحة الإثبات، إخفاء `pending` عن العامة، ووسم المصدر غير الرسمي كـ `source_change` بدل `official_change`، وفكّ الترميز UTF-8 رغم ترويسة `charset` خاطئة أو ترويسة UTF-16 كاذبة، وحسم الترميز من BOM.
