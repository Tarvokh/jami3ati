### الحقيقة المركزية

**المسار الوارد يعمل الآن من أول بايت إلى القرص.** رسالة من `aicha@uca.ma` تدخل
على `127.0.0.1:2526`، تُحلَّل، تُكتب في PostgreSQL + blob store، وتُرفض فوراً إذا
كان المستلم غير موجود. أُثبت ذلك حياً: رسالة عربية، إعادة تشغيل العملية،
والرسالة ما زالت هناك.

**والمسار الثاني لم يعد باباً بلا قفل:** `GET /mail/{id}` و
`GET /api/v1/mailboxes/{id}/messages` يعرضان الرسائل المخزَّنة، والرسالة الخام
تُعاد بايتاً ببايت — لكن كل مسار يقرأ القاعدة يتطلب الآن رمز API. بلا رمز
`401`، وعبر المستأجرين `404`، وبلا قاعدة `503`. الرمز نفسه لا يُخزَّن؛ القاعدة
تحفظ SHA-256 له فقط.

**الحقيقة الجديدة (6 نوفمبر 2026):** المزامنة ليست فجوة، وجسر الهوية ليس فجوة
(§6)، والنسخ الاحتياطي ليس فجوة: `backup.ps1` + `restore-drill.ps1` نجحا
مرتين (عادي ومشفَّر). و**توقيع البريد ليس فجوة**: RSA-2048 وEd25519 يُتحققان
رياضياً على نطاقين، ومنطقة DNS تُفحص آلياً. ما تبقّى هو **الخارجي**: شهادة ACME،
نشر DNS، تقييم Gmail/Outlook، تدفئة سمعة IP، وRspamd وقت التشغيل. أما **RLS**
فلم يبقَ فجوة: صار مُثبتاً سلوكياً على القاعدة، وله endpoint أدلة حيّة
(`/api/v1/control-plane-proof`).

## 3. خريطة التدفق — دورة حياة الرسالة

### 3.1 الوارد (يعمل حتى القرص — 85%)

```
TCP connect :2526
  → 220 tira.local ESMTP Tira Mail
  → EHLO  → 250-SIZE 10485760 / 8BITMIME / HELP
  → MAIL FROM:<aicha@uca.ma>        ✅
  → RCPT TO:<yassine@tira.ma>       ✅ resolve_recipient() → 550 إن لم يوجد
  → DATA                            ✅
  → 354
  → [بايتات خام + dot-unstuffing]   ✅
  → mail-parser                     ✅
  → PgStore::append_message()
       ├─ blobs.put(raw)  sha256     ✅
       ├─ BEGIN
       ├─ SELECT … FOR UPDATE (حصة)  ✅
       ├─ INSERT messages            ✅
       ├─ UPDATE used_bytes          ✅
       └─ INSERT audit_log → COMMIT  ✅
  → 250 2.0.0 Message accepted
```

**ما أُثبت حياً (4 نوفمبر 2026):**

| الاختبار | النتيجة |
|---|---|
| رسالة عربية `=?UTF-8?B?…?=` | فُكّت إلى «السلام عليكم» في القاعدة |
| إعادة تشغيل العملية | الرسالة ما زالت موجودة |
| مستلم غير موجود | `550 5.1.1` عند RCPT، لا open relay |
| نفس الرسالة مرتين | صفّان، **blob واحد** (إزالة تكرار) |
| تجاوز الحصة | `552 5.2.2` |
| `/healthz` | `{"status":"ok","database":"ok"}` — مقلَّص: لا `uptime`/`modules`/`smtp` |

**ما لا يزال يسقط في `tira-smtp` اليدوي:**
- لا STARTTLS → كلمة المرور والرسالة بنص صريح على الشبكة.
- لا AUTH → لا يمكن السماح بالترحيل (relay) لأي عميل.
- لا فلترة → كل ما يُقبل يُخزَّن، بما فيه السبام.

> هذا الخادم **مرشح للإيقاف** لا للتطوير: Stalwart يقدّم SMTP 25/2526 مع
> STARTTLS وAUTH فعلاً (§3.6). لا تبنِ ميزتين متوازيتين.

### 3.2 القراءة (موجود ومُحمى في `tira-api`)

```
GET /api/v1/mailboxes/{id}/messages?limit=&offset=   ✅ JSON، ترقيم، 404/400/503
GET /api/v1/messages/{id}/raw                        ✅ message/rfc822 + nosniff
GET /mail/{id}                                       ✅ HTML مُهرَّب، RTL
  ✅ الرمز مطلوب: Bearer أو كوكي tira_token
  ✅ مستأجر آخر أو خارج mailbox_scope → 404 لا 403
  🟡 IMAP/JMAP يعملان في Stalwart لا هنا (انظر §3.6)
  ⛔ لا بحث، لا خيوط محادثة، لا مرفقات
```

**أُثبت حياً:** القائمة أعادت رسالتين بعنوان عربي مفكوك، والرسالة الخام
أعادت **119 بايتاً مطابقة** لما قُبل عبر SMTP، والصفحة عرضت العربية بـ `dir="rtl"`،
وصندوق غير موجود أعاد **404** لا 500.

### 3.3 الصادر (موجود 40%)


**ما يعنيه هذا:** Thunderbird وApple Mail وOutlook يمكنهم الاتصال **اليوم**
بمحركنا. والحساب لم يعد يُنشأ يدوياً: `tira-provision` يترجم صندوقاً في
`tira-store` إلى `Account` في Stalwart، ويُثبت ذلك في §15. كلمة المرور لا
تُخزَّن في control plane إطلاقاً؛ تُسلَّم للمحرك مرة واحدة ثم تُسقط.

**ما لا يعنيه:** لا شهادة موثوقة (ذاتية التوقيع، SANs `mail.tira.test`,
`tira.test`, `localhost`, `127.0.0.1`)، ولا DNS عام. التوقيع **موجود**:
Stalwart يولّد RSA-2048 وEd25519 ويوقّع بهما، و`dkim-proof.ps1` يتحقق رياضياً

اختبار محلية واحدة ذهبت إلى `Junk Mail`. ولا نسخ احتياطي لمخزن Stalwart. ولا
ترحيل: لم تُنقل رسالة واحدة من PostgreSQL إلى Stalwart، ولا العكس.

## 10. خريطة البحث العربي — التفصيل الذي يقرر النجاح

PostgreSQL **لا يملك stemmer عربياً**. الخيارات:

| الخيار | الميزة | العيب |
|---|---|---|
| `simple` + `pg_trgm` | بسيط، بلا خدمة إضافية | لا تجذيع، «الجامعة» ≠ «جامعات» |
| Tantivy + tokenizer عربي | سريع، Rust أصلي | مكتبة إضافية، فهرسة يدوية |
| Meilisearch | جودة عالية | خدمة خارجية، ذاكرة كبيرة |

**التوصية:** ابدأ بـ PostgreSQL `simple` + **مُطبِّع عربي مخصص** (سطر واحد لكل قاعدة):

```
أ إ آ ٱ  → ا
ى        → ي
ؤ        → و
ئ        → ي
ة        → ه   (بحذر: قد تخلط «مكة»/«مكه»)
حذف التشكيل U+064B–U+0652
حذف التطويل U+0640
```

ثم `tsvector` على النص المُطبَّع + `pg_trgm` للأخطاء الإملائية.
**معيار القبول:** البحث عن «محمد» يجد «مُحَمَّد»، والبحث عن «جامعات» يجد «الجامعة».

### إثبات حيّ للـcontrol plane (7 نوفمبر 2026)

`GET /api/v1/control-plane-proof` (والاسم التوافقي `/api/v1/sovereignty-proof`)
يرفض أن يكون شعاراً. كل حقل فيه مقيس من أثر حقيقي:

| ما يعرضه | كيف يُقاس | متى يفشل |
|---|---|---|
| عزل المستأجرين | معاملة تنزل إلى `tira_app`، تضبط GUC مستأجراً عشوائياً، وتعدّ الصناديق | صف واحد ≠ 0، أو الدور ليس `tira_app`، أو `BYPASSRLS=true` → `200 status=fail` |
| جواهر التاج | `has_table_privilege` على `api_tokens` و`message_recipients` | أي امتياز SELECT/INSERT → `fail` |
| مسار التدقيق | INSERT حقيقي لصف تدقيق داخل معاملة **تُلغى** | رفض أو لا مستأجر → `fail`/`warn`، لا نجاح |
| DKIM | فك SPKI DER وحساب بتات معامل RSA؛ طول مفتاح Ed25519 بالبايت | RSA < 2048 أو Ed25519 ≠ 32 → `fail` |
| DMARC | تحليل سجل `_dmarc` في المنطقة | `p=none` → `warn` (مراقبة، لا إنفاذ) |
| SPF/MX/MTA-STS/TLS-RPT | قراءة السجلات من المنطقة نفسها | غياب SPF/MX → `fail`؛ غياب STS/TLS-RPT → `warn` |
| الأصول الخارجية | فحص HTML المُصيَّر؛ `xmlns` يُستثنى لأنه اسم لا طلب | أي `src/href/url/@import` خارجي → `fail` |
| عمر الأثر | `generatedAt` + sha256 للبايتات المخدومة | أقدم من 7 أيام → `warn` |

قواعد الفشل مقصودة: **`503` فقط عندما تكون الأدلة غير متاحة** (قاعدة غير
متصلة، ملف مفقود، JSON تالف). إذا وُجدت الأدلة وكان الضمان مكسوراً فالجواب
`200` و`status:"fail"` — لأن إعادة المحاولة لا تصلح خطأً أمنياً.
الـendpoint **لا يكتب شيئاً** ولا يدقّق نفسه؛ الاستجابة `Cache-Control:
no-store`؛ وتُخفى المسارات المطلقة والمنافذ وبيانات الاتصال. و`scope.does_not_prove`
يسمّي ما لا يثبته: الاختصاص القضائي، الإقامة الفيزيائية، نشر DNS العام، منفذ 25،
صلاحية ACME، Rspamd، التسليم لدى المزوّدين، وتوقيع الـartifact.

### الحد الذي لا يُتجاوز

1. لا تُضاف سياسة قراءة بلا اختبار كسر: كل سياسة RLS جديدة يجب أن تُثبت أنها
   ترفض فعلاً عند تعطيلها. المتبقي: `domains`/`messages` مباشرة.
2. الشهادة ذاتية التوقيع — لا تُستخدم مع عميل حقيقي.
3. لا تعديل على كود Stalwart قبل حسم D2 (AGPL).
4. لا يُشغَّل مخزنان للرسائل في نفس الوقت. اختر واحداً — والتوصية Stalwart.
5. لا يُنشر `p=reject` قبل المرور بـ`p=none` لمدة 14 يوماً وقراءة تقارير
   `rua`؛ النطاق الجامعي فيه أنظمة قديمة ترسل نيابة عنه، و`reject` المبكر
   يحذف بريداً مشروعاً بصمت.
6. لا يُفعَّل Rspamd بـ`tempFailOnError=true` قبل إثبات أنه يستجيب؛ الخطأ
   هنا يوقف البريد الوارد كله، لا يفلتره.

**معيار نجاح P2 النهائي — تحقّق:** مستخدم يُنشأ بأمر واحد في `tira-store`،
فيظهر في Stalwart خلال ثوانٍ، ويدخل بـ Thunderbird بكلمة المرور نفسها، ويُرسل
ويستقبل — ثم يُعطَّل فيختفي الوصول خلال دقيقة. لا خطوة يدوية واحدة.

**الخطوة التالية الفعلية (7 نوفمبر 2026):** RLS لم يبقَ خطوة — أُنجز وأُثبت
(`0004_rls.sql` + `0005_audit.sql`؛ الدور `tira_app` بلا BYPASSRLS وGUC
معاملاتي؛ دالتا `SECURITY DEFINER` للبحث قبل المستأجر). المتبقي المحلي:
(1) اختبار SQL مباشر لسياسات `domains`/`messages` بلا predicate؛
(2) `has_function_privilege('public', …)` على الدوال؛
(3) تشغيل endpoint الأدلة أمام لجنة التحكيم مع artifact حديث.
وبالتوازي، حين يتوفر DNS: نشر المنطقة بـ`p=none`، ثم `dkim-proof.ps1` على
المفتاح المسحوب، ثم Rspamd runtime، ثم تدفئة IP. لا Leptos قبل هذه الثلاثة.
