# التشغيل المحلي لمستخدمين حقيقيين — Tira Mail

> **الحالة:** هذا الدليل يصف ما هو منفّذ ومقاس في الشجرة الحالية، لا ما هو مخطط.
> كل حساب يُنشأ هنا حقيقي: صف في PostgreSQL، وبصمة Argon2id، وجلسة، وسجل تدقيق.
> لا توجد رسالة نموذجية واحدة، ولا مستأجر مزيّف، ولا صندوق عرض مسبق.

## 1. لماذا وُجد هذا المسار

كان الـ demo يُشغَّل من قاعدة `tira_test`، وهي نفس القاعدة التي تكتب فيها
اختبارات التكامل. القياس بتاريخ 2026-11-17:

| العنصر | العدد في `tira_test` |
|---|---|
| `tenants` | **3,743** (منها 1,570 باسم «Université Cadi Ayyad») |
| `mailboxes` | **4,020** |
| `messages` | **1,684** |
| `api_tokens` | **303** |

أي زائر كان يرى بيانات اختبارات معروضة كأنها مستأجرون حقيقيون. لذلك:

1. قاعدة `tira_dev` منفصلة ونظيفة،
2. الـ API يرفض الإقلاع من قاعدة ينتهي اسمها بـ `_test` أو `_tests`،
3. التسجيل الذاتي محلي فقط،
4. «أرسل لنفسك» يمرّ عبر SMTP حقيقي بدل رسالة مزروعة.

`tira_test` لم تُحذف: التوكن التجريبي القديم `f3716171-…` ما زال صالحًا،
لأن حذف القاعدة كان سيُبطله.

## 2. المتطلبات

- Windows + PowerShell 5.1 (يعمل أيضًا على PowerShell 7).
- Rust عبر `rustup` مع toolchain `stable-x86_64-pc-windows-gnu`.
- MinGW-w64 حقيقي (`C:\tools\winlibs\bin` أو `C:\tools\mingw64\bin`) — سببه
  مشروح في رأس `scripts/dev.ps1`: `dlltool` المرفق مع rustup لا ينشئ import
  libraries على هذا الجهاز.
- PostgreSQL محمول في `C:\tools\pgsql` (يبدأه `scripts/pg-dev.ps1` على المنفذ
  55432، بلا خدمة ولا صلاحيات مدير).

## 3. أمر واحد

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev-local.ps1
```

السكربت ينفّذ بالترتيب:

1. `scripts/pg-dev.ps1` → يشغّل PostgreSQL وينشئ `tira_dev` إن لم تكن موجودة.
2. `cargo build -p tira-api` (يمكن تجاوزه بـ `-NoBuild`).
3. يشغّل `target\debug\tira-api.exe` على `127.0.0.1:8080` بمتغيرات البيئة
   الموضّحة في القسم 6.
4. ينتظر `/healthz` حتى يعيد `200` — أي أن migrations طُبّقت فعلًا.
5. ينشئ المستأجر والنطاق مرة واحدة (idempotent عبر `ON CONFLICT`).
6. يطبع رابط التسجيل.

المخرجات المتوقعة:

```
Tira Mail is running.
  Sign up:  http://127.0.0.1:8080/signup
  Log in:   http://127.0.0.1:8080/login
```

أوقف الـ API بـ `Ctrl+C`. PostgreSQL يبقى يعمل؛ أوقفه بـ
`.\scripts\pg-dev.ps1 -Stop`.

## 4. ما ينشئه السكربت بالضبط

مرة واحدة، في `tira_dev` فقط:

| الصف | المعرّف |
|---|---|
| `tenants` — «Tira local development» | `7a1e0000-0000-4000-8000-000000000001` |
| `domains` — `tira.test` | `7a1e0000-0000-4000-8000-000000000002` |

ثم كل تسجيل ينشئ **صندوقًا واحدًا** في نفس المستأجر والنطاق:

- صف `mailboxes` بعنوان `<local>@tira.test` وحصة 5 GiB،
- صف `mailbox_credentials` ببصمة Argon2id (لا كلمة مرور صريحة، أبدًا)،
- صف `api_tokens` كجلسة ويب `session:web` صالحة 7 أيام،
- صف `audit_log` بالعملية `auth.signup`،
- كوكي `tira_token` (`HttpOnly` + `SameSite=Strict`).

الاسم المعروض اختياري. العنوان يُقبل فقط إذا طابق
`[a-z0-9][a-z0-9._-]{1,31}` (حروف لاتينية صغيرة، أرقام، نقطة، شرطة، شرطة سفلية).
كلمة المرور: 12–128 حرفًا.

الحد: **20 تسجيلًا لكل عنوان IP في 10 دقائق** (نافذة `LoginLimiter` نفسها
المستخدمة لتسجيل الدخول). تجاوزها يعيد صفحة `429`.

### 4.1 اللغات في شاشتَي الدخول والتسجيل

`/login` و`/signup` متاحتان بثلاث لغات: العربية (افتراضي، `dir="rtl"`)،
الفرنسية، والإنجليزية (`dir="ltr"`). النصوص كلها من مصدر واحد
(`crates/tira-frontend/src/i18n.rs`)، فلا نسخة ثانية تنحرف عن الأولى.

الترتيب عند الحل: `?lang=ar|fr|en` ← كوكي `tira_lang` ← ترويسة `Accept-Language`
← العربية. اختيار المستخدم يُحفظ في كوكي `HttpOnly` + `SameSite=Lax` لمدة سنة،
لأن رد `POST` لا يحمل استعلامًا ويجب أن يُرسم بنفس اللغة.

```
http://127.0.0.1:8080/login?lang=fr
http://127.0.0.1:8080/signup?lang=en
```

التبديل روابط عادية، فيعمل بلا JavaScript. `assets/auth.js` يضيف ثلاث تحسينات
فقط: إظهار/إخفاء كلمة المرور، تنبيه عدم تطابق التأكيد، وتحذير Caps Lock؛ لا
شبكة ولا تخزين. وبلا JavaScript تبقى النماذج والتحقق على الخادم كما هي.

**اللغات الآن:** قشرة صندوق البريد كلها (الوارد، القارئ، التحرير، الملف
الشخصي، النسخة المطبوعة) وصفحات الفشل (400/404/503) بثلاث لغات
(عربي/فرنسي/إنجليزي)، وتبديل اللغة فيها روابط نسبية `?lang=fr` تحفظ المسار
الحالي وتُثبَّت في كوكي `tira_lang`. الترجمة تشمل واجهة الرسالة فقط: الموضوع
والمرسل والنص تبقى كما وردت (`dir="auto"` عليها، و`dir="ltr"` على العناوين
والمعرّفات)، والتواريخ والأحجام تُنسَّق حسب اللغة.

## 5. مسار «أرسل لنفسك»

الصندوق الجديد فارغ. صفحة الوارد الفارغة تعرض زر **«أرسل رسالة إلى نفسك»**
يربط إلى:

```
/mail/<mailbox_id>/compose?to=<your-address>@tira.test
```

عند الإرسال يحدث ما يلي فعليًا، بلا اختصارات:

```
POST /mail/<id>/send
  → tira-api يبني الرسالة ويوقّع الهيدرز
  → relay = 127.0.0.1:2525 (tira-smtp المدمج، STARTTLS=0 مسموح للـ loopback فقط)
  → tira-smtp يتحقق من RCPT عبر resolve_recipient
  → append_message: blob على القرص + صف messages + تحديث used_bytes
  → إعادة توجيه إلى /mail/<id> مع إشعار الإرسال
```

فتح الرسالة يعرض الجسم الحقيقي وترويسات التحقق البريدي كما استلمها الخادم.
لا يوجد مجلد «مُرسَل» في المخطط الحالي؛ الرسالة تظهر في الوارد لأنك أرسلتها
إلى نفسك.

## 6. متغيرات البيئة

السكربت يضبطها لك؛ `.env.example` يوثّقها كلها. أهمها:

| المتغير | القيمة المحلية | الأثر |
|---|---|---|
| `TIRA_DATABASE_URL` | `postgres://postgres@127.0.0.1:55432/tira_dev` | القاعدة |
| `TIRA_BLOB_ROOT` | `./data/blobs-dev` | منفصل عن blobs العرض |
| `TIRA_BIND` | `127.0.0.1:8080` | loopback فقط |
| `TIRA_DEV_MODE` | `1` | يفعّل `/signup` |
| `TIRA_DEV_DOMAIN` | `tira.test` | نطاق كل الحسابات المحلية |
| `TIRA_COOKIE_INSECURE` | `1` | يسمح بكوكي الجلسة فوق HTTP على loopback فقط |
| `TIRA_SMTP_ENABLE` | `1` | يشغّل `tira-smtp` المدمج |
| `TIRA_SMTP_ADDR` | `127.0.0.1:2525` | مستقبل البريد المحلي |
| `TIRA_SMTP_HOST` / `PORT` | `127.0.0.1` / `2525` | relay المستخدم في الإرسال |
| `TIRA_SMTP_STARTTLS` | `0` | نص صريح، مرفوض لغير loopback |

**لماذا `blobs-dev` منفصل:** عامل التنظيف `purge_unreferenced_blobs` يحذف
الـ blobs التي لا تشير إليها قاعدة البيانات المتصلة. لو شارك `tira_dev` مجلد
`data/blobs` مع `tira_test`، لحذف أجسام رسائل العرض بعد 24 ساعة.

## 7. الحاجز على قواعد الاختبار

في `crates/tira-api/src/main.rs`: إذا انتهى اسم قاعدة `TIRA_DATABASE_URL` بـ
`_test` أو `_tests`، يرفض الـ API الإقلاع برسالة تسمّي القاعدة وتطلب قاعدة
غير اختبارية. للتجاوز الواعي فقط:

```powershell
$env:TIRA_ALLOW_TEST_DB = "1"
```

هذا الحاجز لا يمنع كل خطأ، لكنه يمنع تحديدًا الخطأ الذي حدث: خدمة أشخاص من
قاعدة يكتب فيها `cargo test`.

## 8. الإيقاف والتنظيف

إيقاف الـ API: `Ctrl+C` (السكربت يوقف العملية التي بدأها في `finally`).

إعادة ضبط `tira_dev` بالكامل (حسابات ورسائل وblobs):

```powershell
& "C:\tools\pgsql\bin\dropdb.exe" -h 127.0.0.1 -p 55432 -U postgres tira_dev
Remove-Item -Recurse -Force .\data\blobs-dev
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev-local.ps1
```

`dropdb` يحتاج أن لا يكون أحد متصلًا بالقاعدة: أوقف الـ API أولًا.

## 9. أعطال شائعة

| العرض | السبب | الحل |
|---|---|---|
| `Port 8080 is already listening` | نسخة قديمة من `tira-api` تعمل | أوقفها أو استخدم `-Port 8090` |
| `Port 2525 is already listening` | عملية SMTP أخرى | أوقفها أو استخدم `-SmtpPort 2526` (السكربت يضبط الـ relay تلقائيًا) |
| `refusing to serve from a test database` | `TIRA_DATABASE_URL` يشير إلى `tira_test` | استخدم السكربت، أو غيّر الرابط |
| صفحة «النطاق المحلي غير موجود» عند التسجيل | `tira_dev` أُنشئت لكن السكربت لم يُكمل التهيئة | أعد تشغيل `dev-local.ps1`؛ التهيئة idempotent |
| `tira-api did not become healthy in 90s` | فشل migrations أو تعارض منفذ | اقرأ `%TEMP%\tira-dev-api.err.log` |
| الإرسال يعيد «الإرسال غير مهيّأ على هذه النسخة بعد» | `TIRA_SMTP_HOST` فارغ | شغّل عبر السكربت لا يدويًا |
| بعد التسجيل تعود كل صفحة إلى `/login` | كوكي الجلسة `Secure` فوق HTTP | اضبط `TIRA_COOKIE_INSECURE=1` (السكربت يضبطه) |
| الإرسال يفشل بـ «plaintext SMTP refused» | الـ relay ليس loopback | للاختبار المحلي فقط: `127.0.0.1` |

## 10. ما ليس هنا (بصراحة)

- **لا تسجيل عام.** `/signup` غير موجود إطلاقًا إلا مع `TIRA_DEV_MODE=1`،
  ومحمي كذلك بشرط أن يكون الاتصال من loopback. لا يوجد مسار تسجيل على
  الإنترنت، ولا نية لإضافة واحد قبل الهاكاثون.
- **لا Stalwart/IMAP في هذا المسار.** البريد يُخزَّن ويُقرأ عبر Tira؛ عميل
  IMAP خارجي يحتاج ربط المحرك، وهو خارج نطاق التشغيل المحلي.
- **لا DKIM signing فعلي.** الكود يتحقق من توقيعات SPF/DKIM/DMARC الواردة
  ويعرضها؛ توقيع الصادر ليس منفّذًا، ولا يجوز الادعاء به.
- **لا بيانات نموذجية.** إن أردت رسالة في الصندوق، أرسلها لنفسك.
